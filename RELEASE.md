# CAT 0.1.0 release procedure

The release consists of the `cat-tooling` wheel and source distribution, the repository documentation, and `uv.lock`. The shell samplers are package data; cluster jobs generated by CAT do not import CAT at runtime. CATPlot is packaged separately and remains optional.

The working tree's unreleased FreqBall consolidation is documented in [CHANGELOG.md](CHANGELOG.md). Rebuild after reviewing these changes; an existing `dist/` wheel may predate them. Outstanding deployment checks and next-version work are listed in [ROADMAP.md](ROADMAP.md).

## Install on a workstation or cluster

Install uv using the [official installation instructions](https://docs.astral.sh/uv/getting-started/installation/), then work from the repository root:

```bash
cd ~/Repo/PhononTools
uv python install 3.12
uv sync --locked
uv run --no-sync cat-tools --version
uv run --no-sync cat-tools phono3py sample --help
uv run --no-sync cat-tools phono3py audit --help
uv run --no-sync cat-freqball --help
```

The base installation includes numerical and phonon analysis dependencies. Select additional features explicitly:

```bash
uv sync --locked --extra structure --extra bonding --extra ordering --extra visualization
```

Keep `--locked`: a mismatch between `pyproject.toml` and the lock file should fail rather than silently resolving a different environment. `uv run --no-sync` uses the installed environment without removing extras. See [uv's lock/sync documentation](https://docs.astral.sh/uv/concepts/projects/sync/). The first sync needs access to package sources or a populated uv cache.

For interactive use, `source .venv/bin/activate` exposes all `cat-*` commands. This Python environment is separate from the module stack selected for jobs. For example, CAT's locked Phono3Py 4.4 analysis environment can generate jobs that load `palma/2023a foss/2023a phono3py/2.7.0` on the compute node. The runtime `python`/`PHONO3PY_PYTHON` and `phono3py` executable must belong to the same module environment.

## Upgrade while calculations are running

Do not replace a checkout or environment used by active Python jobs. Install the release in a separate checkout/environment and use a new `--job-dir` for future jobs. Existing generated shell scripts retain their original commands; upgrading CAT cannot repair already queued JDOS jobs. Wait for those tasks to finish, audit their output, then generate missing-temperature recovery jobs.

CAT never submits sampling or recovery jobs without `--submit`. The separate VASP convergence generator retains its documented submit-by-default behavior; use `--no-submit` when only preparing those jobs.

## Validate

Use a fresh environment so an older editable installation cannot hide dependency or packaging problems. This does not change the working `.venv`:

```bash
export UV_PROJECT_ENVIRONMENT="$PWD/.venv-release"
uv sync --locked --extra structure --extra bonding --extra ordering --extra visualization
uv pip check --python "$UV_PROJECT_ENVIRONMENT/bin/python"
PYVISTA_OFF_SCREEN=true "$UV_PROJECT_ENVIRONMENT/bin/python" -m unittest discover -s tests -v
uv lock --check
```

The suite uses temporary fixtures and fake submission/native executables. It does not submit cluster jobs or run VASP. Tests cover scientific analysis, ordering, generated JDOS jobs, temperature recovery, and RTA/Wigner collection. Legacy command routing is tested with a fake 2.7 runtime that implements the original JDOS writer failure; this is not a full legacy numerical-equivalence test. An additional integration test executes a generated JDOS job with the installed Phono3Py on a small synthetic FC2 model and verifies both temperature files.

CATPlot recipe validation is skipped unless CATPlot is installed. To validate that integration, add the local plotting package to the test environment, then rerun the recipe tests. Do not run an exact `uv sync` between adding CATPlot and testing it, since it is not a dependency of `cat-tooling`.

FreqBall's own static plots use Matplotlib from the visualization extra and do not require CATPlot. Its regression tests cover native Phonopy PDOS agreement, plane normals in oblique cells, projection sum rules, named mass tables, and execution of a copied standalone bundle with CAT imports blocked. Regenerate/check the bundle when modifying shared implementation files:

```bash
python 3_Analysis/scripts/sync_freqball_standalone.py
python 3_Analysis/scripts/sync_freqball_standalone.py --check
```

## Build and inspect

Versioning uses setuptools-scm. Development checkouts may show a development suffix. The explicit build variable creates the intended release version without requiring a tag on an uncommitted checkout:

```bash
SETUPTOOLS_SCM_PRETEND_VERSION_FOR_CAT_TOOLING=0.1.0 uv build --out-dir dist
```

This produces `dist/cat_tooling-0.1.0-py3-none-any.whl` and `dist/cat_tooling-0.1.0.tar.gz`. Install the wheel into an isolated environment and run `cat-tools --version`, `cat-prepare --version`, and every calculation command's `--help` from outside the repository. Verify the wheel includes `cat_utilities/phono3py/qmesh_sampling.sh` and the VASP shell resources; the source archive must include the lock file, docs and tests. It must also contain the complete standalone FreqBall directory and its source synchronization script. Smoke-test `cat-freqball --help`, `cat-freqball plot --help` and `cat-freqball mass-scan setup --help` from the installed wheel. Historical `OLD_Workflows` data are excluded from the source distribution; they remain in the repository.

Review and commit the intended changes before tagging `v0.1.0`. Building these artifacts does not create a Git tag, publish a release, or upload to PyPI.
